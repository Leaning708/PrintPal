## 2. 关键实现与设计决策

### 2.1 未结账单切换器（+N 折叠）

- 溢出折叠机制：chip 一行放满，其余折叠进「+N」浮层（完整/紧凑/极简三模式共用
  `ChipOverflowStrip` 一套实现）。
- **测宽用离屏原型**：`MeasureChipWidth` 用 chip 模板实例化离屏 `ContentPresenter`
  测量——刚重建的容器直接 `Measure` 拿不到真实宽度（ContentPresenter 未进布局树）。
- **LayoutUpdated 单遍同步**：溢出计算挂在布局宿主的 `LayoutUpdated` 里，宽度/账单数
  变化时一次性按当前宽度应用。**不要加回「延迟修正 / ±1 逐张收敛」**——那会引入
  多轮重排（震动）与任务表滚动条闪现（教训，见 [troubleshooting.md D6](troubleshooting.md#d6-窗口缩放时任务表横向滚动条闪现未修复已知问题)）。
- 误差处理：原型与真实排版有 ±1px 级误差，由 `ClipToBounds` 吸收，肉眼不可见。
- 宽度/数量未变时跳过重算（幂等收敛，避免自身可见性变更触发的布局风暴）。

### 2.2 模式位置记忆（侧车文件）

- 位置/大小按模式存侧车文件 `%LOCALAPPDATA%\PrintPal\window-bounds.json`
  （**同步写盘**，避开数据库 WAL/锁时序——曾出现强杀前异步写丢失导致恢复旧值）。
- 保存时机：模式切换、关窗/退出、移动/缩放后 500ms 防抖；恢复时机：模式切换、启动。
- **坑**：`SetModeAsync` 曾在 `_applyingMode` 置位**之后**调 `SaveModeBounds`，
  而后者开头检查该标志直接跳过——模式切换从不保存位置（死代码）。保存必须在
  标志置位之前。
- 恢复后钳制在虚拟屏幕内（显示器变更时防止整窗消失）；最大化状态按 `RestoreBounds` 保存。

### 2.3 TextBox 模板的双倍 Padding（坑）

- 自定义 TextBox 模板里 `Margin="{TemplateBinding Padding}"` 与 TextBox **原生**
  的 Padding 文字缩进**叠加**——实际渲染 = 2 × Padding + 边框。
- 例：全局样式 Padding 10 → 实际文字距左 21px（用户感觉「异常的大」）；
  搜索框要 23px 的视觉间距需设 Padding 11。
- **其他自定义模板若用 `Margin="{TemplateBinding Padding}"` 同样有此叠加**，调整
  内边距时先实测渲染值再定数值。
- 搜索框占位文字的显隐条件是「空且未聚焦」（`MultiDataTrigger`）——聚焦时只显示
  光标，避免占位文字与光标重叠；点列表空白处 `Keyboard.ClearFocus()` 让搜索框
  失焦、占位重现。

### 2.4 模式更名（全量替换的操作经验）

- 「简洁 → 紧凑」「打印记录 → 收银台」两次全量更名均用有序 sed（**长标识符优先**，
  避免前缀误伤）+ 少量手工 Edit。
- 保留不动的：任务数据模型（`JobRow`/`PrintJob`/`_jobRows`）、对任务的操作方法名、
  CHANGELOG 历史条目（按惯例保留原称）。
- 持久化键同步更名 + 旧值兼容映射（`uiMode="Simple"` → `Compact`）。

## 4. 自动化验证的陷阱（本次实测教训）

对 WPF 应用做 UI 自动化验证时：

- **`MoveWindow`（Win32）缩放会被 WPF `Width` 属性弹回**——WPF 窗口的 Width DP
  是显式设置的；外部 Win32 尺寸调整在下次布局时被覆盖。程序化改尺寸要么走 UIA
  `TransformPattern`，要么接受回弹并改用位置类断言。
- **应用隐藏在托盘时（`Hide()`），元素仍在 UIA 树中且不参与布局**——拿到的
  BoundingRectangle 是冻结的旧值，勿据此断言。
- **单实例互斥锁**：`taskkill` 后 `cmd start` 若互斥量仍被占用（时序），新进程退出、
  旧实例复活——「改了代码没生效」的常见假象；先确认进程 PID 与启动日志时间戳。
- **应用日志在双路径**：服务模式写 `C:\ProgramData\PrintPal\logs`，启动目录日志在
  `%LOCALAPPDATA%\PrintPal\logs`；先按模式确认读哪份。
- UIA 查询返回的 BoundingRectangle 可能是过期缓存（元素移动后未刷新），
  跨进程像素级断言（GetPixel 扫描）不可靠——本次曾把背后终端误判为滚动条。
