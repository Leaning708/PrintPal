# ADR-011：打印机能力并入打印机页（取消独立路由规则）

- 状态：**已确认并实施（2026-11-11）**
- 日期：2026-11-11
- 关联：ADR-010（账单亲和路由）、`docs/ui.md`、`docs/architecture.md`

## 1. 背景

ADR-010 把"路由规则"改成了纯能力声明（无优先级、无条件、无默认打印机），路由选择完全由
「候选集 + 同单亲和 + 跨账单均衡」完成。此时规则页已经不再有任何"路由"逻辑，只剩"这台机能打什么"，
与打印机配置重复，且"同一打印机不能重复声明同一组合"等校验都是这种重复造成的复杂度。

## 2. 决策

1. **删除独立的路由规则页 / 编辑窗口 / 导航项**，能力声明合并到**打印机编辑窗口**（UI 名称「打印能力」）；
2. **能力语义改为产品模型（笛卡尔积）**：勾选支持的纸张 × 颜色 × 单双面即代表全部组合可打；
   不再精确声明"某组合"（例如不再支持"仅 A4 彩色、A3 只能黑白"这种非对称声明）；
3. 数据库 `Printers` 新增 `RoutingCapabilityJson`（字段名保留，UI 叫打印能力）；
4. 路由逻辑不变：候选集 = 能力覆盖且启用/格式兼容的打印机；无候选 → `Unrouted`；
   候选内按「同单优先 → 跨账单均衡」挑选（ADR-010 保留）。

## 3. 理由

- 打印店实际配置通常就是"这台机支持哪些纸、是否彩色、是否双面"，产品模型足够；
- 一台机一份能力，天然消除重复声明校验、规则命名、规则列表等一整套多余概念；
- 检测能力（测试连接）只作参考与预填，路由依据始终是人工声明，符合"能力由人配置"的原则。

## 4. 后果

- **能力可能被高估**：若机器真的存在非对称能力（如 A3 仅黑白、A4 才彩色），产品模型无法精确表达；
  这是明确接受的取舍（用户确认），必要时可后续再引入"组合例外"。\n- **不做升级迁移**（2026-11-11 决定）：产品尚未正式使用，删库重装即可；已移除价格表/路由能力的历史迁移代码，\n  新库直接按当前 schema 建表。
- 迁移：旧 `RoutingRules` 按打印机合并（任一条为空 = 任意；否则取并集）写入 `RoutingCapabilityJson`，
  然后 `DROP TABLE RoutingRules`；没有旧规则的打印机按检测能力预填，仍无则「未声明（不参与路由）」。
- UI：打印机页新增「路由能力」列（未声明会提示）；编辑窗口新增能力勾选区与「按检测结果填充」。
- 人工选择目标：只列候选集内的打印机，与自动路由一致（不支持的机器不出现）。

## 5. 备选方案（未采用）

- **保留独立能力页**（改名"打印机能力"）：仍需两处配置，只是换名字。
- **精确组合矩阵**（行=纸张，列=颜色/单双面）：表达能力强，但 UI 复杂、与"勾选支持彩色即所有纸张都支持彩色"的预期不符。
